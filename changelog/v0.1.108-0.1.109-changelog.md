# v0.1.108 → v0.1.109

## Fixed

- Prevent the Settings updater from offering an older repository release as “latest.”
- Block different commits that reuse the installed semantic version instead of treating them as an upgrade.
- Inspect the candidate release version and required broker protocol before enabling installation.
- Show installed and required broker protocols with an actionable trusted-setup message.
- Repeat version-direction and broker checks inside the update worker before build or deployment.
- Send update notifications only for a strictly newer release that the installed broker can run.

## Compatibility

- The root broker protocol remains 22, so installations already healthy on protocol 22 do not require another trusted setup run for this release.
- Servers on an older broker protocol still require trusted `sudo bash setup.sh` before installing a release that depends on protocol 22; the ordinary updater remains non-root.
- Rollbacks are not performed through “Install latest” and require a separate deliberate recovery procedure.
