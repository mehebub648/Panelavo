# v0.1.65 → v0.1.66

- Removed vendor-owned runtime fallbacks for the base domain, update repository, and wildcard-registration service.
- Added explicit environment and panel-settings fields for the optional wildcard endpoint/base-domain pair; setup now requires a base domain and can infer an update source from a compatible HTTPS checkout origin.
- Kept Settings usable when no update repository is configured, and preserved an existing updater-state repository as a compatibility fallback.
- Replaced default-domain UI copy with configuration-neutral DNS guidance and added no-vendor-default coverage.

Existing persisted settings and environment values remain compatible. Operators who relied on an implicit wildcard service must configure the documented matched environment pair; no `setup.sh` rerun is required when those values are supplied through the deployed `.env.local`.
