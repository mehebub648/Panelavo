# v0.1.121 — Native connected-server workspaces

- Replace cross-origin iframe and delegated-cookie switching with the managing panel's native interface backed by the existing signed, allow-listed Fleet action protocol. The browser remains on the managing panel and sends no session cookie to a connected server.
- Match the local Super Admin navigation while a connected server is selected. Websites, website sections, Domains, AI access, Resources, Information, VPN, About, Users, Audit, and panel update, notification, monitoring, and security settings operate against the selected server through its existing actor-aware services.
- Permit the selected server's existing one-time database and phpMyAdmin workflows through the signed channel while retaining their original confirmations, expiry, site-user boundary, and one-time-secret handling.
- Reuse bounded keep-alive TLS connections for peer RPC calls while continuing to validate public DNS answers, pin the selected address, verify the exact TLS hostname, disable redirects, send no cookies, and enforce request and response limits.
- Remove the obsolete full-panel session action, iframe wrapper, cross-site ticket endpoint, delegated cookie, and conditional framing policy. Normal Panelavo pages remain frame-denied.
- Keep Fleet protocol 1 and broker protocol 24. Existing connection identities, per-peer keys, nicknames, address revisions, replay state, sites, and all other `.data` remain unchanged.
