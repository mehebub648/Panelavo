# Panelavo 0.1.96 → 0.1.97

## What changed

- Replaced the linked-service workflow with Project Endpoints that inherit live write access from their parent project.
- Added broker-verified discovery of high loopback listeners owned by the project's Unix boundary, with foreign, wildcard/public, and CloudPanel-reserved ports rejected.
- Added private pending reservations for stopped services and ownership plus HTTP verification before a public reverse proxy is created.
- Added health-gated active port changes with automatic restoration of the previous NGINX upstream when the new target fails.
- Added create, list-port, verify, update, and delete MCP endpoint tools, matching browser API and Settings controls; the older linked-service tools remain compatible aliases.
- Prevented generic child-site updates and raw vhost editing from bypassing the endpoint ownership and rollback contract.

## Compatibility and migration

- Broker protocol increases from 17 to 18. Run trusted `sudo bash setup.sh` before deploying this application release.
- Existing linked-service metadata remains compatible and is presented as active Project Endpoints.
- A pending endpoint is intentionally non-public until its selected listener is running, project-owned, loopback-only, and HTTP-reachable.
