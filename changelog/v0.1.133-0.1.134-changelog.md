# v0.1.134

Routine MCP website operations no longer request a second Panelavo confirmation. Site-user terminal commands, PHP/Node/Python/static deployments, artifact releases, and ordinary file inspection or editing now run after the existing live website-write authorization. This fixes clients returning declined elicitation even after the user has authorized deployment in chat.

Destructive actions, backup restoration, host recovery and unknown operations retain their existing one-use confirmation. Role checks, site assignments, command bounds, audit logging and the unprivileged site-user boundary are unchanged. No broker or data migration is required; rebuild and reload only Panelavo.

Added direct MCP tools for listing, reading, writing and uploading files, reading site logs, and restarting the site’s own PM2 or rootless Compose application. These share the existing actor services, validation, audit trail and preflight checks.
