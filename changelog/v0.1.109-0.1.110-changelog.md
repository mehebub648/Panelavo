# v0.1.109 → v0.1.110

## Production database exposure

- Databases remain private by default. A site writer can expose only one selected database through a unique TLS hostname and generated port, with read-only/allowlist defaults, dedicated schema-only credentials, one-time password display, exact-hostname confirmation, and current-password verification.
- ProxySQL enforces TLS, schema lock, port-bound credentials, and connection caps. Nginx Stream enforces CIDR access and per-IP limits. Revocation and database/site deletion close the listener and remove the dedicated credential first.
- Raw MySQL/MySQL X ports become loopback-only. Setup accepts an operator-supplied wildcard certificate or generates a private Panelavo client CA.

## Production safety

- Broker protocol moves from 22 to 23. Trusted setup installs the database gateway and denies CloudPanel's unrestricted `clpctlWrapper` to non-service Unix users; the Panelavo service keeps only its exact root-owned broker command.
- Boot-time schedulers now run without waiting for a panel visit. Database gateway reconciliation is five-minute, storage hygiene is fifteen-minute, and host security-maintenance checks are six-hour.
- Automatic storage cleanup starts at 75%, tightens at 90%, and never prunes volumes, containers, databases, backups, or application files. At 92% or below the dynamic free-space reserve, known storage-growing actions pause while recovery and deletion remain available.
- Trusted setup configures bounded PM2 rotation, and newly initialized rootless Docker daemons receive bounded local container-log defaults without replacing an explicit external logging driver.
- New installs enable resource alerts with a 75% disk threshold. Setup enables daily unattended security updates without automatic reboot, and the Information page reports pending security work and reboot state.

## Upgrade requirement

Run trusted `sudo bash setup.sh` before deploying this release. The ordinary in-panel updater cannot install broker protocol 23, ProxySQL, the Nginx Stream boundary, database listener changes, firewall rules, or the sudo boundary.
