# v0.1.110 → v0.1.111

## Production recovery hardening

- ProxySQL now uses a dedicated localhost-only MySQL/MariaDB monitor account and TLS for its loopback backend, verifies TLS by its negotiated session cipher on current MySQL, Percona, and MariaDB releases, and no longer shuns an otherwise healthy database after installation.
- Database gateway readiness is section-scoped. A gateway fault keeps every database endpoint fail-closed and prevents endpoint mutations without blocking Panelavo sign-in, site listings, or unrelated site operations.
- The CloudPanel wrapper denial still blocks website users, while root and CloudPanel's own service account retain the administrative path required by trusted setup and recovery.
- Inactive UFW installations cannot be activated from an SSH setup unless the operator separately confirms tested provider-console recovery with `UFW_CONSOLE_RECOVERY_READY=true`.
- Active project endpoints can move only to a freshly verified, healthy loopback port owned by the parent project; the existing post-change health check and automatic rollback remain in force.

## Upgrade requirement

Run trusted `sudo bash setup.sh` from this release before using the ordinary updater. Keep `ENABLE_UFW` unset during a remote upgrade unless provider-console recovery has been tested and explicitly acknowledged.
