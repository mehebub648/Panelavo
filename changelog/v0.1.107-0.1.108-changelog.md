# v0.1.107 → v0.1.108

## Fixed

- Treat a configured application port owned by another website or system process as a blocking collision instead of deployment-ready.
- Require the final Operations health check to prove the loopback listener belongs to the current site before accepting its HTTP response.
- Show stopped, created, or unhealthy Compose entry containers in deployment readiness.
- Reserve new managed application ports in `30000–39999`, separate from stable site ids and CloudPanel's PHP-FPM pool allocation range.
- Inventory CloudPanel upstreams, PHP-FPM pools, and live TCP listeners before suggesting, creating, or changing an application port, with a fresh broker-side check at mutation time.

## Compatibility

- Existing configured application ports remain authoritative and supported; changing one no longer changes the website id, Unix user, category, or system domain.
- The root broker protocol moves from 21 to 22. Run the trusted `setup.sh` before installing this release through Panelavo's in-panel updater.
